# Contributing to Hexman

Thanks for your interest in contributing! Hexman is an open-source, Electron-based API testing tool, and contributions of all kinds are welcome — bug reports, feature ideas, documentation, and code.

## Before you start

This project is licensed under the [Apache License 2.0](LICENSE). By submitting a contribution, you agree that it will be licensed under the same terms (see [Developer Certificate of Origin](#developer-certificate-of-origin) below).

All participants are expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Reporting bugs

Open a [GitHub Issue](../../issues) using the bug report template. Include:
- Steps to reproduce
- Expected vs. actual behavior
- Your OS and Hexman version
- Screenshots or logs if relevant

For security vulnerabilities, do **not** open a public issue — see [SECURITY.md](SECURITY.md).

## Suggesting features

Open a [GitHub Issue](../../issues) using the feature request template. Describe the problem you're trying to solve, not just the solution — it makes it easier to evaluate alternatives.

## Submitting changes

1. Fork the repository and create a branch from `main`.
2. Make your changes, keeping commits focused and descriptive.
3. Open a pull request against `main` describing what changed and why.
4. Link the related issue, if any.

Small, incremental pull requests are easier to review than large ones. If you're planning a large change, open an issue first to discuss the approach.

## License headers

New source files should carry an SPDX license identifier at the top, matching the project license:

```
// SPDX-License-Identifier: Apache-2.0
```

Use the comment syntax appropriate to the file type.
